## BINDING RULES — import verbatim into every workstream plan

1. **Contract tests from day one.** The first runnable slice in every service loads or validates against v1.0.0. A route/event is not done until its success and declared Problem/event shapes pass contract tests. Contract changes require a separately approved amendment; implementation may not “fix” the contract locally.
2. **No `sudo` from application code.** Node, Python, browser, and worker code may not invoke `sudo`, a shell, or arbitrary privileged commands. Privileged work crosses `/run/eduscope/helper.sock` and is limited to this fixed verb allowlist: `net.apply`, `volume.mount`, `volume.unmount`, `volume.format`, `usbhub.cycle`, `led.set`, `system.poweroff`, `firmware.check`, `firmware.apply`, `firmware.rollback`, `relay.reload`, `smart.read`. Arguments are schema-validated; the helper uses `execve`/argv and `SO_PEERCRED`; there is no generic-exec verb.
3. **Inventory KEEP behaviors are non-negotiable.** A workstream cannot close while any KEEP item assigned to it lacks the concrete verification identified in the inventory-coverage ledger below. Implementation may change; the observable capability must survive.
4. **The mock adapter stays.** `packages/api-client/src/mock` remains the demo/UI-development environment and contract-regression harness. Every real-adapter or backend contract change must keep mock responses/events and contract-honesty tests green.
5. **Single writers and async commands stay binding.** Only the owning state machine writes its state. A `202 CommandAccepted` is acceptance, not completion; the resolving event must arrive by its contract deadline.
6. **No direct frontend networking.** All panel and quiz REST/WS/WebRTC signaling goes through `packages/api-client`; no component calls `fetch`, `WebSocket`, or a media-signaling endpoint directly.
7. **No task may depend on an open decision.** Encountering one stops that workstream. Update this master plan and ask for review; do not choose an option in code.
8. **Master-plan scope is fixed at workstream planning time.** A JIT workstream plan may expand a task but may not add/drop contract ownership or KEEP coverage. If reality conflicts, update this master plan and flag the gate.

## Reading conventions and global dependency order

- **Size** is focused engineering time and is capped at one day per task.
- **Files** are the creation/change boundary, not an exhaustive execution file list.
- **Contract ownership** is the authoritative exact-once ledger. A name appearing in tests or a screen-consumption note does not create a second implementation owner.
- **Tests** always name both unit/internal tests and contract tests. “Contract regression” means the full v1 schema/operation/event coverage gate even when a task owns no new public element.
- **Verification** is the observable proof used at the workstream gate.

```text
A pipeline-manager
  └─> B core-api
        ├─> C AI services
        └─> D quiz-service (B provides the device client/test peer; D owns server ops)
A + B + C + D ─> E real adapters and screen swaps
A + B + C + D + E ─> F device bring-up
```

Workstream plans are written and executed in that order. B builds AI/quiz clients against fakes; C and D later replace those fakes and own cross-service verification. E may start a domain only after its backend tasks are green. F starts only after all target-device domains are real.

## Workstream B — core-api

**Outcome:** Fastify/TypeScript core-api is the single writer for device state, exposes every panel/admin operation, emits every panel/admin event, brokers preview signaling, and persists crash-safe state in SQLite/Drizzle. D owns the four quiz-sync server operations; B owns the outbound client and `sync.hello`.

> **WORKSTREAM B GATE FLAG — pipeline-manager encoder-profile ingress drift (2026-08-18, resolved 2026-08-19).** JIT planning found that B-24's required proof (a per-channel encoder change is consumed by the next A pipeline) is not executable against the current Workstream A code. `RecordStartBody`/`LiveStartBody` and `RecordRequest`/`LiveRequest` carry no effective profile, and the builders always call `get_profile(...)` without overrides; `get_profile` also lacks overrides for the v1-editable `gop`, `rateControl`, and `audioBitrateKbps` fields. This contradicts `core-api.md` §11, `domain-model.md` §4.9, `pipeline-manager.md` §3.2, and the B-24 verification below. Before B-24 or B-38 executes, the Workstream A gate must accept and land an internal-only correction: record/live start requests carry `{videoBitrateBps, fps, gop, rateControl, audioBitrateBps}`, the builders apply those values to re-encoding profiles (passthrough remains unaffected), and A tests prove a streaming override does not change the local/default profile. B converts the public v1 Kbps fields to Bps at this boundary. This changes no public v1 contract element, B task, contract owner, or KEEP assignment; it adds an explicit prerequisite so the master plan does not silently claim an integration path that does not exist.
>
> **Resolution (2026-08-19):** Landed. `RecordStartBody`/`LiveStartBody` (`services/pipeline-manager/src/pipeline_manager/api/routes.py`) and `RecordRequest`/`LiveRequest` (`.../pipelines/record.py`, `.../pipelines/live.py`) carry the five optional override fields; `get_profile(...)` (`.../pipelines/profiles.py`) validates and applies `gop`/`rateControl`/`audioBitrateBps` alongside the existing `videoBitrateBps`/`fps`/`container` overrides. Passthrough call sites pass no overrides, so remux profiles are unaffected. New/extended tests (`tests/pipelines/test_profiles.py`, `test_record.py`, `test_live.py`) prove the override reaches the rendered encoder argv and that a record-side override does not leak into the live default profile and vice versa. `pipeline-manager.md` §2.2/§3.2 updated to match. B-24 may proceed.

### Mixed-mode flag design

`/config.json` is loaded before either app creates a client. It is generated from deploy-owned provisioning at boot, not baked by Vite/Next and not editable from the UI.

```json
{
  "apiBaseUrl": "/api/v1",
  "quizBaseUrl": "https://quiz.example.edu",
  "adapters": {
    "default": "mock",
    "overrides": {
      "auth": "real",
      "recording": "real"
    }
  }
}
```

Rules:

- `default` is `mock` in demo/UI-dev and `real` on a completed device. `overrides` is allowed only in development/integration; the Phase-4 gate requires `{default:"real", overrides:{}}`.
- Domains are `auth`, `recording`, `channels`, `sourcesAudio`, `preview`, `libraryExport`, `uploads`, `provisioningHealth`, `alerts`, `devicePower`, `storage`, `network`, `encoder`, `streamTargets`, `firmware`, `users`, `aiQuiz`, `logs`, and `studentQuiz`.
- `createRoutedClient` owns one mock and one real client and routes each method through a static operation→domain map. There is no component-level switch.
- Panel events are filtered through a static event→domain map, then merged. An event from the inactive adapter for its domain is discarded. Preview is its own channel. Student realtime belongs wholly to `studentQuiz`.
- Connection state is tracked per domain. A real WS outage dims only real live domains; mock domains continue. A sequence gap invokes full resync on the affected real client; commands are never replayed.
- The real panel WS authenticates only with the v1 `Sec-WebSocket-Protocol` subprotocol (DR-05). Token refresh reconnects the socket. Scoped export/log flows still become subscribed through their REST entry calls.
- Mock and real adapters run the same generated-response/event validators. A real endpoint is not swappable until its domain’s contract tests pass against a running service.

### Install script outline

`deploy/install.sh` is an idempotent, root-only deployment tool; root authority exists only during installation, never in app code.

1. **Preflight:** verify supported OS/arch, free space, network/time, Node/Python/GStreamer versions, required RK3588 elements, manifest completeness, display/storage topology, and artifact checksums. Abort before mutation on mismatch.
2. **Snapshot:** back up owned configs and current unit enablement to a timestamped rollback directory; never overwrite an unrelated administrator file.
3. **Packages/runtime:** install pinned OS packages, Node production workspace, isolated Python venvs, Vosk/Tesseract assets, nginx-rtmp/stunnel, Chromium, uhubctl/smart tools. Verify hashes for models/bundles.
4. **Identity/paths:** install sysusers/tmpfiles, service groups, state/runtime/media paths, and strict permissions.
5. **Application artifacts:** install A/B/C/helper builds, panel static build, and prompt assets; run SQLite migrations once. Campus D deployment remains a separate documented command.
6. **Provisioning/secrets:** validate the supplied per-device manifest; write deploy-owned provisioning and hashed/bearer secrets atomically; render non-secret runtime config.
7. **Platform config:** install udev/ALSA/X11/kiosk/nginx/stunnel files; run syntax/fixture validation before activating them.
8. **Units:** install/verify units, `daemon-reload`, reload udev, enable helper/runtime/A/B/C/kiosk and distro relay units in dependency order.
9. **Start and smoke:** start services, wait on bounded health checks, run curl/WS/2-minute-record smoke, verify journal has no secret/no sudo, then mark install successful.
10. **Failure/rollback:** stop only newly started units, restore the snapshot, reload units/config, restart the prior known-good set, and print the exact failed stage/evidence path.

### Expanded on-device verification procedures

These are the final tasks of the F JIT plan; none may be replaced by a unit test or simulator.

1. **Clean provisioning (F-09).** Flash the named supported image; record its hash. Connect the frozen devices, recording disk, three displays, LAN, and mic. Run the single documented installer command with a valid manifest. Reboot twice. Capture `systemctl --failed`, unit versions, migration version, runtime config (redacted), and a Playwright real-adapter boot/login screenshot. Pass: zero failed Eduscope units, no `<TBC>` values, no mixed overrides, no browser prompts, and a playable 2-minute clip.
2. **90-minute continuous recording (F-10).** Start with a clock/video test source and audible periodic marker. Keep local composite recording active for 90 minutes while source tiles remain live. Stop from UI; observe targeted SIGINT and `Got EOS`, never global kill. Run `ffprobe` on TS and MP4, compare duration to recorded duration (tolerance recorded), seek near start/middle/end, check A/V sync and file growth. Pass: finalized/seekable files, one recording/manifest, queue inserted exactly once, LED off after stop.
3. **Pause/resume and recovery (F-10).** During a fresh lecture: pause 60s, confirm LED off and channels’ “still streaming” truth, resume, repeat twice, then stop. Verify monotonically indexed split segments and merged/separate deliverables. Repeat with (a) `kill -9` record consumer while live, (b) restart B while paused, (c) hard device reboot while live.
