# core-api — Service Design (Phase-3, prompt 11)

> Phase-3 design artifact. The Node backend that implements **contract v0.6**
> ([contracts/openapi.yaml](../../contracts/openapi.yaml),
> [contracts/events.md](../../contracts/events.md)) on the device, as the single
> writer of every device-side state machine
> ([state-machines.md](state-machines.md)) over the entities of
> [domain-model.md](domain-model.md), driving
> [pipeline-manager](pipeline-manager.md) and the AI services
> ([ai-services.md](ai-services.md)), and syncing with the campus
> [quiz-service](quiz-service.md).
>
> **Rules this document obeys:**
> 1. **Contract v0 is implemented unchanged.** Anything this design was tempted
>    to change in `contracts/` is *flagged* in §15 for the prompt-12 drift
>    review — nothing is changed here.
> 2. **Every contract operation and WS event is owned by exactly one module**
>    across core-api / ai-services / quiz-service — the coverage table is §13.
> 3. **Every behavioral-inventory KEEP/CHANGE item not owned by
>    pipeline-manager appears here** — the coverage table is §14.
>
> Ends at a **STOP gate** (§16).

## 0. Stack & process shape

| Concern | Choice | Why / source |
|---|---|---|
| Runtime | **Node 22 LTS + TypeScript** (strict, ESM) | Brief; shares `packages/shared` zod schemas with the panel and quiz-service |
| HTTP framework | **Fastify 5** | Brief default; no ADR overrides it. First-class JSON-schema validation (we compile the zod mirrors), `@fastify/websocket` for the two sockets, plugin-per-module encapsulation |
| Validation | zod schemas from `packages/shared/src/schemas/**` — the same objects the mock adapter validates | openapi.yaml Conventions ("the zod mirror … is what the mock adapter and the future backend validate against") |
| DB | **SQLite (WAL) + Drizzle**, driver `better-sqlite3` | ADR-001 (D-03). Synchronous driver deliberately: writes are short and funneled through one writer (§3.1) |
| Ids | ULID (`ulidx`), generated by the owning module | INV-G-1/2, DM-13 |
| Password hashing | argon2id (argon2 package), cost tuned on the RK3588 | B-21/B-40 (never hash-of-hash) |
| Tokens | Short-lived JWT access (10 min) + rotating opaque refresh persisted on `AuthSession` | PF-17, INV-AS-1/2 |
| Logging | **pino** (JSON to stdout) → **journald** via systemd; curated `LogEntry` rows for AD-7 | PF-15, §12 |
| Process | **One systemd service, one Node process** (`eduscope-core-api`), localhost SQLite, no cluster | ADR-001 single-writer; PRD §6 budget — the board is shared with the pipelines and the kiosk browser |

Serving topology (B-61 successor, INV-NC-2): nginx terminates the single origin
and serves the built panel SPA as static files with **runtime config**
(`/config.json`, generated at boot from provisioning — never baked at build
time); `/api/v1` and the two WS upgrades proxy to core-api on `127.0.0.1:5000`.
Media bytes are served by core-api itself (authenticated Range streaming, §6.4)
— never an unauthenticated nginx `location /record/` (B-37, G-7). CORS is
same-origin only (B-64).

Internal (not module-owned routes): the **pm-bridge** — the pipeline-manager
client (REST commands + `GET /events` SSE ingest + `GET /status` resync) —
lives inside M2 because machine 1a/1c/5a are the consumers of every `evt.pm.*`
event (pipeline-manager §3.1). M5 subscribes to the same ingest stream for
`device.health` fields (capture card, publisher states). One SSE connection,
one dispatcher, two consumers.

**Module dependency rule.** Modules communicate through (a) the database and
(b) an in-process typed event bus (`emitDomainEvent`) that the WS hub and other
machines subscribe to. No module calls another module's route handlers. Every
domain event in the bus corresponds to a row in the §13 event table — nothing
is emitted that the catalog does not name (SM-R-3).

## 2. Command plane: 202-accepted, single writer

Every state-machine command follows one shape (openapi Conventions, SM-R-2):

1. Route handler validates the request (zod) and **authorizes** from `role` +
   ownership server-side (INV-U-4, G-AUTH-OWNER).
2. Class A guards run synchronously against fresh DB/probe state; a refusal
   returns `4xx Problem` with the named code and **creates nothing** (§0.4 of
   the machines).
3. The command is handed to the owning machine's **command executor** — a
   per-machine serial queue (§3.1) — and the route answers
   `202 CommandAccepted {commandId, acceptedAt, resolveBySec: T-CMD-RESOLVE}`.
4. The executor performs side effects (pm calls, DB transaction, quiz-sync
   push), transitions the machine, and emits the resolving event through the
   bus → WS hub. Class B failures surface as events within their deadline
   (R-06/R-07 ≤ 5 s).

`resolveBySec` is `T-CMD-RESOLVE` (10 s) everywhere except `powerOffDevice`
(where it is the not-halted threshold, CG-16).

## 3. Data layer (ADR-001, D-03)

### 3.1 Engine configuration & the single-writer rule

- One database file: `/var/lib/eduscope/core.db` on the **system** volume
  (never the recordings disk — a swapped disk must not take the DB with it).
- `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`,
  `busy_timeout=5000`.
- **Single-writer funnel:** all writes go through per-machine serial executors
  (§2) over one `better-sqlite3` connection. `better-sqlite3` is synchronous,
  so a write transaction is a single JS turn — no interleaving, no `SQLITE_BUSY`
  from ourselves. Long work (merge, upload, export, probes) happens **outside**
  transactions; transactions only persist outcomes (kills B-23's
  event-loop-blocking `execSync` class of bug).
- Reads (lists, snapshots, media lookups) use the same connection; they are
  sub-millisecond at this dataset size (hundreds of sessions).
- Every mutating write records actor + instant (INV-G-6) — enforced by a
  Drizzle helper (`withActor(tx, actor)`) that the executors must use.
- Nightly `VACUUM INTO` snapshot to the system volume as the backup story;
  the DB is small (media lives on the recordings volume).

### 3.2 Schema (Drizzle tables)

Physical mapping of domain-model §4–§9. Types: `text` for ULIDs/enums/ISO
instants (stored UTC with offset, INV-G-3), `integer` for bools/counters,
`integer` (64-bit safe via `bigint` mode) for byte counts/durations, `text`
JSON columns validated by zod at the boundary. Enum values are CHECKed in SQL
and typed in Drizzle.

deploy layer. Secrets never enter SQLite, responses, events, logs, or audit
`before/after` (INV-ST-1, INV-AU-3, INV-UJ-5).

### 3.3 Migrations plan

- `drizzle-kit generate` → numbered SQL files in
  `services/core-api/migrations/NNNN_name.sql`, committed and code-reviewed;
  applied **at boot, before listen**, in one transaction per file, recorded in
  `_migrations`. A failed migration aborts startup loudly (never a half-migrated
  service).
- **Seeds are migrations too**: `source_roles`, `layout_presets` (imported from
  `packages/shared` at generation time — one geometry definition, DM-6),
  `channel_configs` (3 rows), `retention_policy`, device-default
  `encoding_profile`, the four `physical_inputs` skeleton rows and their
  `source_bindings`. Seeds are idempotent upserts keyed by natural PK, so
  re-running is safe; a *changed* seed value ships as a new migration.
- Rollback story: firmware updates are A/B (ADR — INV-FU-2); the DB file is
  snapshotted before `firmware.apply` runs migrations, and rollback restores
  the snapshot. Individual down-migrations are not authored (appliance model —
  roll the whole slot back).

### 3.4 Legacy data on fielded devices — **no import path, by decision**

The brief asks for "the legacy-data import path for fielded devices." Per
**ADR-001** and **ADR-024 (A-21)** the PM confirmed **no fielded-device
migration**: no accounts, no recordings, no settings are carried from legacy
Jetson units. This design therefore ships **no importer**, and that is a
decision to hold, not an omission:

- Rollout is pilot-then-staged-swap (INT-9); a legacy room keeps its legacy
  unit until swapped. Recordings on a retiring unit drain through the legacy
  upload path before decommissioning (operator runbook item, deploy layer).
- Users are re-created via the Excel bulk import (AD-6/B-44) — the sanctioned
  "import path" — with forced reset (INV-UI-2). Institute-sourced users
  re-sync under `[D-02b]` when that lands.
- The only artifact intentionally recognized from a legacy disk is **nothing**:
  a legacy-named file under a mounted recordings volume is a *foreign file*
  and is ignored per INV-RF-4/RET-5.

If the PM reverses this, the importer is a standalone one-shot deploy-layer
tool (read legacy MySQL dump → emit Excel roster + optionally re-queue media),
not core-api code. Flagged in §15 so prompt 12 sees the brief/ADR conflict.

## 4. Recording orchestrator (M2) — the single writer of machine 1a

### 4.1 Structure

Three components, one serial executor:

- **Machine 1a executor** — the only code that writes `lecture_sessions.state`
  and opens/closes `recording_segments` (SEG-1). Consumes: panel commands
  (R-01/08/10/11/21/22), pm-bridge events (R-05/06/07/12/13/16/17), storage
  events from M5 (R-19/20), boot recovery (BR-1..9).
- **Machine 1c executor** — channel consumers (`meeting`, `streaming`):
  CH-01..CH-10, preflight orchestration (A-10; the relay itself is prompt 11's
  streaming-relay design), `channelActivations` bookkeeping.
- **pm-bridge** — typed client for pipeline-manager §3: REST commands
  (`POST /consumers/record`, `/consumers/{id}/stop {mode:eos}`, `/consumers/live`,
  `/consumers/meeting`, `/consumers/projector`, `/publishers/*`,
  `POST /device/led`), plus the SSE `GET /events` subscription with automatic
  `GET /status` full-resync on reconnect. Maps pipeline-manager's error
  taxonomy (§3.4 there) onto Class A refusals / Class B events exactly per its
  §3.5 command→machine table.

### 4.2 Start path (R-01) — implementation order

1. Class A guards, all server-side: `G-NO-ACTIVE-SESSION` (the partial unique
   index is the backstop), `G-PROVISIONED`, `G-VOLUME-MOUNTED`, `G-STORAGE-OK`
   (fresh probe ≤ 500 ms), `G-CHANNEL-VALID`. Refusals return the named
   `Problem` codes (`recorder.busy` + owner meta for LP-6, `storage.critical`,
   `provisioning.incomplete`, `volume.unavailable`, `config.invalid`).
2. One transaction: create `LectureSession(starting)` with generated title
   (A-07 `titlePattern`), hall snapshot, `sourceSnapshot` from bindings
   (INV-SB-2), `aiEnabledAtStart`; create `Recording(capturing)`; open no
   segment yet.
3. Outside the transaction: ensure publishers (pm), compute `outputPath` for
   segment 0 (`<recordings-volume>/sessions/<sessionId>/seg-000[-<streamKey>].ts`
   — the path is *told* to the manager, never parsed back, B-02/SEG-7), then
   `POST /consumers/record` (+ enabled channels via 1c).
4. On `evt.pm.consumer.running` + `G-CONSUMER-CONFIRMED` (file growth — the
   manager's job) within `T-START-CONFIRM`: transaction → `recording`, open
   segment(index 0), LED blink, arm 2a (Q-01), request quiz session (Z-01).
   Emit `recording.state{recording}` + `recording.segment{capturing}`.
5. On failure/timeout: R-06 (`error`, no segments) or R-07 (stopping, segments
   exist — SM-R-4). Partial consumers are stopped; alert + log within 5 s (G-1).

Pause/resume/stop follow the machine tables verbatim (R-08..R-14); each resume
opens `seg-NNN` with a fresh path. Stop additionally: disarm 2a (Q-09), close
open publication (Q-34) and quiz session (Z-05) via M8, stop channel consumers,
then hand the artifact to M3 (machine 1b) on entering `finalizing`.

### 4.3 Session heartbeat & boot recovery

- `last_heartbeat_at` written every `T-SESSION-HEARTBEAT` (5 s) while
  non-terminal — a single-column UPDATE outside the executor queue.
- On boot, after pm-bridge has a first `GET /status` snapshot (≤
  `T-BOOT-RECOVERY` 20 s): run the BR-1..BR-9 decision table exactly as
  specified — adopt (BR-1, using the manager's orphan adoption), auto-resume
  within `T-RECOVERY-WINDOW` (BR-2, `startReason=recovery`, J-4 banner via
  `system.alert{session.recovered}`), else finalize (BR-3/5/6), defensively
  finalize extras (BR-9). Recovery emits through the same executor so ordering
  invariants hold.

### 4.4 Machine 5a projection & takeover

- pm-bridge telemetry updates the in-memory per-role health (HL-01..HL-09
  debounces are pipeline-manager's; core-api applies the `T-HEALTH-STALE`
  6 s staleness rule locally so a dead SSE link degrades to `unknown`, never
  last-healthy — INV-DH-2) and writes `physical_inputs.presence_state`.
  `GET /sources/status` reads this projection; `sources.status` events fan out
  on transition.
- R-21 takeover: `G-ADMIN`, sets `takeoverBy/At`, writes
  `AuditLogEntry(takeover)`, revokes the displaced panel `AuthSession`
  (`revokedReason=takeover` — the same vocabulary S-01/S-06 read, CG-14), and
  re-broadcasts `recording.state` with `takeoverByDisplayName`.
- R-22: `powerOffDevice` (route in M5) consults this module: refused with
  `poweroff.refused` + `system.alert` while any session is non-terminal
  (CG-17); otherwise M5 invokes the root helper verb `system.poweroff` (§8).

## 5. Library & artifacts (M3) — machine 1b, exports, retention

### 5.1 Machine 1b executor

- Entered from M2 on `finalizing`: probe every segment file (ffprobe),
  RA-01/RA-02 decision (`segmentCount>1` ∨ container conversion needed).
- **Merge worker**: a supervised child process per merge (never on the event
  loop — B-23): ffmpeg concat per `streamKey` across segments (SEG-4),
  `truncated`/`crash` segments included (SEG-5), then remux `.ts → .mp4`
  (`kind=derived`, the deliverable). Idempotent: outputs are checksummed and
  detected on re-entry (BR-7). Watchdog `T-MERGE-WATCHDOG`, retries
  `T-MERGE-RETRY`, then RA-04 `failed` (+ alert; **no** upload job — INV-UJ-3).
  RA-07 (`retryMergeRecording`, admin) resets the counter.
- RA-03/RA-02 → `ready`: mark files `finalized` + `isUploadable`, create the
  UploadJob **exactly once** (U-01, INV-UJ-2) via M4.
- RA-06 delete (admin command, retention, disk pressure): real
  `deleted_at/by/reason` columns, files removed, `LectureSession` row survives
  (INV-LS-7), `AuditLogEntry` for admin deletes, `upload.job{cancelled}` via
  M4 (U-10).

### 5.2 Retention sweep (RET-1..RET-6, ADR-007/[D-15])

Runs every `T-RETENTION-SWEEP` (15 min) + on `upload.job{done}` + on storage
threshold crossings (from M5). Pure DB-driven decisions (INV-RP-2): age from
`retention_delete_after`, upload outcome from `upload_jobs`, order
uploaded-oldest-first, `neverDeleteUnuploaded` honored (RET-2 raises
`retention.blocked`), foreign files ignored (RET-5, B-20). All deletions go
through RA-06 — the sweep owns no state.

### 5.3 Library reads

`listRecordings`: server-side ownership filter (lecturer pinned to own rows —
INV-RC-5, B-31), server-side `q`/`state`/`ownerUserId` filters, cursor =
opaque base64 of `(startedAt, id)` keyset. `uploadState` badge joined from
`upload_jobs` (derived, never stored twice).

### 5.4 Media route

`getRecordingMedia`: per-request authz (owner-or-admin, INV-RC-6), resolves
`recording_files.path` under the mounted volume **at use time** (B-51),
streams with HTTP Range (206) via Fastify reply-from-stream; `?download=1`
adds Content-Disposition. Closes B-37.

### 5.5 USB export

- **udev watcher** (`udev` netlink via `node-udev`-class lib, with a
  `lsblk --json` fallback poll) maintains the current `UsbVolume[]` snapshot —
  system + recordings volumes are never listed (INV-EX-2). Emits `usb.volumes`
  scoped to AuthSessions holding the export-flow TTL subscription (CG-3, §9.3).
- `createExport`: expands recordings → file set, **server-side free-space
  backstop** (`export.insufficient-space`, CG-21), spawns a copy worker
  (streamed copy with fsync; progress from real bytes copied — INV-EX-1, B-32),
  `export.job` events scoped to the requesting AuthSession (B-38). Cancel stops
  the worker and removes partial target files; sources are never mutated
  (INV-EX-3).

## 6. Upload queue (M4) — machines 3a/3b

### 6.1 Persistence & scheduler

Jobs and parts are **persistent rows** (survive any restart); the scheduler is
a DB-driven loop: every 5 s (and on `upload.job` row changes) pick the single
runnable job (`state=queued`, `next_attempt_at ≤ now`, `blocked_by IS NULL`),
concurrency **1 job / 1 part** (U-02 — the WAN uplink and the board don't
benefit from parallelism). All transitions U-01..U-10 and UP-01..UP-05 exactly
per the machine tables; `attempt`, `failure_class`, `next_attempt_at`,
retry history surfaced on AD-9 rows.

### 6.2 Backoff & failure classification (§4.4 of the machines, CG-20)

Backoff table 30 s → 2 min → 8 min → 30 min → 2 h → 6 h×3, ±20 % jitter,
dead-letter after attempt 8. Classification is **structural, not string-parsed**
(INV-RF-1): the adapter returns a typed error
`{class: connectivity|server|permanent, detail}`; `connectivity` does **not**
consume attempts (retries at the 6 h cap indefinitely; `upload.offline` alert
after `T-UPLOAD-OFFLINE-ALERT` 24 h), `server` consumes attempts, `permanent`
dead-letters after 2. `failureClass` is stored and mirrored on `upload.job`
events. Part `missing` ⇒ U-08 immediate dead-letter (B-28 made visible).

### 6.3 Upload timing — no windows (**flag: brief vs ADR-006**)

The prompt asks for "window gating (inventory rules)". The inventory's windows
(B-22) were **retired by ADR-006 (D-13)**: `enqueuedAt = now` on
`Recording ready`, immediate auto-upload, no instant/scheduled toggle, manual
re-enqueue (U-09) as the only operator control. This design implements
**ADR-006**; the only gating that exists is structural (`blockedBy=merge`
until `G-UPLOADABLE`, INV-RC-2/B-34) plus the connectivity-aware backoff. If
the PM wants windows back, it is a `queued → holding` guard + a schedule
entity — listed in §15 for prompt 12 visibility, not built.

## 7. Auth (M1) & users (M7)

- **Login** (LP-1): one endpoint, both roles; `User.source` local|institute;
  distinguishable `auth.invalid-credentials` vs `auth.account-disabled`
  (CG-10). Argon2id verify; institute-source auth is `[D-02b]`-dependent
  (until then institute users hold a local hash from import).
- **Sessions**: `AuthSession` row per login; access JWT (10 min) carries
  **only** `{sub, role, sid}` (INV-AS-1); refresh rotation invalidates the old
  token (hash compare); revocation is effective immediately because every
  request loads the session row (INV-AS-2) — cheap in SQLite.
- **Reset lock**: `mustResetPassword` gate on every surface except
  change-password / me / logout (INV-U-3, CG-13); change-password enforces the
  CG-12 composition server-side.
- **Authorization**: a static route→requirement map compiled from the contract
  (`x-required-role: admin` ⇒ `G-ADMIN`; owner-gated commands ⇒
  `G-AUTH-OWNER`), evaluated per request from the DB row (B-43 tightened; the
  UI's visibility is a convenience only).
- **Users CRUD + Excel import** (AD-6, B-44): import parses the workbook
  in-memory (`exceljs`), validates all rows (empty cell, in-file duplicate,
  existing username, invalid role/format), **all-or-nothing** transaction
  (INV-UI-1), `mustResetPassword=true` on every created row (INV-UI-2), the
  file is never written to disk (INV-UI-3). Delete keeps recordings with a
  tombstone owner (INV-U-5).

## 8. Provisioning & device (M5)

- **Provisioning read** (AD-10, ADR-011/[D-20]): the deploy layer owns
  `/etc/eduscope/provisioning.json` (+ secrets). core-api reads it **per use**
  with an mtime-invalidated cache (INV-DP-3 — B-26's boot-frozen flag cannot
  recur); never writes it (INV-DP-1). `GET /provisioning` is the secret-free
  read view.
- **Device health**: aggregates the storage probe, SMART (`smartctl -j`, via
  root helper read-only verb), NTP (`timedatectl show`), pm-bridge publisher
  states + capture-card state; persists the singleton snapshot; emits
  `device.health` on change + 60 s. Stale pm telemetry reads `unknown`
  (INV-DH-2).
- **Machine 5b** storage pressure: probe cadence `T-STORAGE-PROBE-REC/IDLE`,
  thresholds from `retention_policy`, hysteresis, fail-closed on probe failure
  (G-STORAGE-OK). Emits `storage.status` (embedding the full policy so warning
  text quotes real values — INV-RP-1, B-53) and drives R-02/R-19/RET-3/RET-4.
- **Volumes** (AD-4, B-51/B-52): `registerStorageVolume` resolves by UUID via
  `blkid`, mounts through the root helper (systemd mount unit, no fstab
  accumulation), no service restart, no nginx surgery (INV-SV-2).
  `formatStorageVolume` is one guarded operation: `confirmText` must equal the
  label/uuid, refused while any session is non-terminal (INV-SV-3), format via
  root helper (ext4 — NTFS-on-Linux is not carried), progress via
  `storage.status`/alerts.
- **Firmware** (AD-5, B-49): orchestrates the deploy-layer updater through the
  root helper (`firmware.check`/`firmware.apply`): signed artifact only
  (INV-FU-1), refused while non-terminal, A/B slot with rollback (INV-FU-2),
  DB snapshot before migration (§3.3), progress as `firmware.state` events.
- **Alerts**: the `SystemAlert` store + `T-ALERT-REEVALUATE` (30 s) re-raise
  loop (INV-SA-1); every raise/clear also writes a `LogEntry` (INV-SA-2);
  recording-affecting alerts flush to the panel within 5 s (INV-SA-3).

### 8.1 Privileged-action helper (target-architecture §3.7 — no sudo from app code)

A separate root systemd service `eduscope-helper`, listening on
`/run/eduscope/helper.sock` (unix socket, mode 0660, group `eduscope`), with
`SO_PEERCRED` checks restricting callers to the `core-api` and
`pipeline-manager` service users. Protocol: one JSON request per connection
`{verb, args, requestId}` → `{ok, detail}`. **Fixed verb allowlist — the enum
is the security boundary; there is no generic exec:**

| Verb | Args (strictly validated) | Used by | Replaces |
|---|---|---|---|
| `net.apply` | `{interfaceName ∈ known ifaces, config: NetworkConfigShape}` — writes a systemd-networkd profile + `networkctl reload` | M6 network apply | B-46's netplan + SPA rebuild |
| `volume.mount` / `volume.unmount` | `{uuid}` — transient systemd mount unit under `/media/eduscope/<uuid>` | M5 | B-51 fstab/nginx surgery |
| `volume.format` | `{devNode ∈ current block devices, fs:"ext4", label}` | M5 | B-52 |
| `usbhub.cycle` | `{location, port}` from provisioning (uhubctl) | pipeline-manager watchdog (HL-21) | B-39 |
| `led.set` | `{mode: on|off|blink}` (GPIO) | pipeline-manager | B-05 |
| `system.poweroff` | `{}` | M5 (after R-22 guard) | B-50 |
| `firmware.check` / `firmware.apply` / `firmware.rollback` | `{version?}` — drives the A/B updater | M5 | B-49 |
| `relay.reload` | `{configDigest}` — reload the templated nginx-rtmp relay config | streaming-relay (prompt 11) via M6 | B-58 |
| `smart.read` | `{devNode}` — `smartctl -j`, read-only | M5 | B-53's raw `df` |

Every invocation is argv-exec'd (`execve`, no shell — B-63 class), logged to
journald with caller + args, and rate-limited per verb (e.g. `usbhub.cycle`
≤ 2/hour — the HL-21 budget enforced at the privilege boundary too).

## 9. WS hub (M9)

### 9.1 Event socket (`GET /api/v1/ws`)

- Upgrade authenticated with the bearer token (`?token=` **or** subprotocol —
  both accepted so the C-8 hardening pick stays contract-neutral; Phase-3
  default: subprotocol, because tokens in query strings leak into logs).
- Per-connection state: `seq` counter, subscription scopes, a bounded outbound
  queue. On subscribe: emit the **snapshot set** exactly as events.md §1
  (recording.state, channel.state ×3, sources.status ×role, storage.status,
  device.health, ai.countdown, current ai.set, open quiz.publication +
  quiz.session, uncleared system.alerts) — read from the same projections the
  REST mirrors serve (C-9: mirrors, not second truths).
- **Fan-out**: the in-process domain-event bus feeds a router that maps each
  event to its audience (broadcast, panel-only, admin-only, or scoped — the
  events.md §1 scoping table). Serialization happens **once** per event, then
  buffers are written per connection.
- **Backpressure**: if a connection's outbound queue exceeds 256 events or
  1 MB, the hub drops the connection (client reconnects and resyncs via
  snapshot — the seq-gap rule makes this safe and simple; no per-client replay
  buffer exists).

### 9.2 Throttling (events.md §6 budget)

| Stream | Policy |
|---|---|
| `audio.levels` | sampled from pm telemetry at ≤ 10 Hz, **suppressed entirely** when no panel-client is connected |
| `quiz.session` joined-count / `syncState` | coalesced ≤ 1/s |
| `quiz.responses` | forwarded per `sync.answers` batch (quiz-service already coalesces ≤ 1/s) |
| `upload.job/part`, `export.job` | emitted on transition + ≥ 5 % progress steps (progress accumulated, not per-chunk) |
| `storage.status` / `device.health` | on transition + 60 s resync; `ai.countdown` on transition + 15 s |
| everything else | on transition only — silent at steady state |

### 9.3 Scoped-subscription registry (CG-3)

An in-memory map `authSessionId → {stream, scope, expiresAt}` written by the
REST entries: `GET /exports/targets` → `usb.volumes`;
`createExport`/`getExport` → `export.job(jobId)`; `GET /logs` → `log.entry`.
TTL 120 s, refreshed by continued reads, cleared on session end. The hub
consults it for the three scoped streams; there is **no** client→server WS
message (events.md §1).

### 9.4 Preview signaling socket (`GET /api/v1/ws/preview`, events.md §3)

Same auth. Per connection ≤ 1 active negotiation (a new `offer` closes the
previous). The hub validates the role is `online` (machine 5a), then brokers
SDP/ICE between the panel and the **thumbnails consumer's** WebRTC endpoint
(`POST /consumers/thumbnails/start` on pipeline-manager; media is device-LAN
only, no TURN). Source-offline mid-negotiation ⇒ `error{source-offline}`.
Preview death never touches publishers/consumers (INV-CC-2 spirit). The real
transport internals are ADR-022 / CG-2 Wave-8 work; this hub owns only the
signaling envelope, which is already contract-fixed.

## 10. Quiz gateway & AI studio (M8)

Owns machines 2a–2d, 4a, 4d and every `/ai/*`, `/quiz/*` operation. Three
clients live here:

1. **ai-services client** — drives stt/slide session lifecycle and calls
   question-service per the contracts in [ai-services.md](ai-services.md) §2–4;
   ingests their SSE events and persists `TranscriptSegment` / `SlideCapture`
   rows (the services own nothing persisted).
2. **quiz-sync client** — outbound REST to quiz-service (`quizSyncCreateSession`
   Z-01, `quizSyncCloseSession` Z-05, `quizSyncPublish` Q-30/31,
   `quizSyncClosePublication` Q-33/34/35) plus the device-initiated WS
   `wss://{quizServerBaseUrl}/api/device/v1/stream` (events.md §4):
   `sync.hello{answerWatermark}` on (re)connect, ingest `sync.answers` (upsert
   `answer_projections`, replace-never-edit INV-AP-1; emit `quiz.responses`),
   `sync.participants` (projection joined-count → `quiz.session`),
   `sync.heartbeat` both ways every 5 s. Machine 4d drives
   `syncState` from silence windows (Z-30/32) and replay recovery (Z-31/33).
   The stored watermark is `MAX(seq)` persisted with each answer batch —
   durable, so replay after any crash is idempotent.
3. **projector client** — `POST /consumers/projector {mode, questionPayload}`
   on pipeline-manager, called only after quiz-service acks
   (publish-before-project, DM-9/INV-QPUB-3). The payload carries question +
   join-QR data and **never leaderboard data** (INV-QZ-3 is enforced by
   construction: this module simply has no code path that sends it).

Machine specifics implemented per the tables: countdown 2a with
`T-COUNTDOWN-RESYNC` 15 s emits and `nextAt`-based local ticking (INV-G-7);
generation 2b with `inputWindow` computed from the previous set's
`toOffsetMs`, provenance columns, per-item validation (INV-Q-1/2), supersession
Q-16 sparing lecturer-authored questions (INV-Q-3); question immutability after
`sent` (INV-Q-4) with the audited rejection; publication 2d ordering on Q-31
(close previous → isShowing → projector switch → publishedAt). Every question
mutation writes exactly one `AuditLogEntry` (INV-Q-5, INV-AU-2) **plus** a
Session-category `LogEntry` (contract C-3 note).

Leaderboard (`getLeaderboard`) is computed on read from `answer_projections`
with the shared DM-10 formula from `packages/shared` (points = 10 × correct,
dense rank, accuracy 0 when answered = 0) — never stored (INV-LB-1), `stale`
from machine 4d.

## 12. Logging & observability (PF-15, AD-7)

Two planes, deliberately separate:

- **Operational logs**: pino JSON on stdout → journald (systemd captures;
  `journalctl -u eduscope-core-api`). Child loggers per module with bound
  `{module, sessionId?, commandId?}`. Level from env; DEBUG never contains
  payload bodies. Secrets are structurally absent (they never enter the
  process outside the secret-store module, which logs only refs). Log rotation
  and shipping are journald's problem — the deploy layer configures
  `SystemMaxUse`.
- **Product log store** (`log_entries`): the **curated** AD-7 surface — every
  user-observable state-machine failure (INV-LE-2), INFO/WARN traffic per the
  taxonomy `{Auth,System,Hardware,Session}` × `{INFO,WARN,ERROR}`, written by
  a single `logStore.write()` helper that also bridges the entry onto the bus
  as `log.entry` for subscribed AD-7 live tails (§9.3). Append-only (INV-LE-1),
  size-capped by a rotation policy (delete oldest beyond N rows / M days —
  a policy constant, not user-facing config). pipeline-manager and the AI
  services emit their product-log entries by calling an internal
  `POST /internal/logs` (localhost, shared token) so `service` attribution
  (`pipeline-manager`, `ai`) is honest; their stderr still goes to journald.
- **Audit** (`audit_log_entries`): §9.3 of the domain model; written inline in
  the owning executors (INV-AU-2), never from route handlers.

## 16. Open questions & STOP gate

Defaults taken here (cheap to change now):

1. **`better-sqlite3` (sync) over `libsql`/async** — single-writer executors
   make sync the simpler correctness story. Confirm with the tech lead.
2. **Media served by core-api streams** (not nginx `X-Accel-Redirect`) — keeps
   authz per-request in one place; nginx accel is a later optimization if
   Range-streaming CPU shows up in the Phase-4 bench.
3. **Helper protocol = unix socket + JSON + SO_PEERCRED** (over sudoers-per-verb)
